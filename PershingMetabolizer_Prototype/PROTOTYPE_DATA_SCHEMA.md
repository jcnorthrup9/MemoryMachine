**Date:** June 29, 2026
**Author:** Gemini Code Assist
**Status:** Schema Approved.

## 1. Purpose

This document defines the JSON data structure for the `site_data.json` file. This file will be generated by the Python analysis engine (`generate_prototype_data.py`) and consumed by the JavaScript visualization (`PershingMetabolizer_Prototype/index.html`) to render the site and its intervention zones.

## 3. Schema Breakdown

*   **`site_dimensions`**: An object holding the real-world width and height of the park in feet, derived from the SVG's bounding box. This allows the frontend to establish a correct scale.
*   **`boundary_svg_path`**: A single, complete SVG path string that defines the true outline of Pershing Square. This will be extracted directly from `pershingRhinoPlanView.svg`.
*   **`grid_size`**: The analytical grid dimension (e.g., 30 for a 30x30 grid) used by the Python solver. This helps the frontend map grid-based data, like `dig_zones`, back to the visual model.
*   **`zones`**: The main data object containing arrays for each type of intervention.
    *   **`shade` & `green_space`**: Arrays of polygon objects. Each polygon is a list of `{x, y}` coordinate points in the same coordinate system as the `boundary_svg_path`. This allows for drawing precise, freeform shapes.
    *   **`dig_zones`**: An array of objects representing the "puncture" cells identified by `urban_interference_solver.py`.
        *   `grid_x`, `grid_y`: The 0-indexed coordinates on the analytical grid.
        *   `depth_ft`: The calculated excavation depth for that cell.
        *   `score`: The intervention score that determined the dig action, which can be used for visualization (e.g., color intensity).
