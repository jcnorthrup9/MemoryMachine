### 1. Canopy Engine (new feature, full stack)
- `frontend/src/paintCategories.js`: new `canopy` paint brush (continuous weight, like `canyon` — not thresholded to boolean).
- `frontend/src/components/PaintOverlay.jsx`, `DiagramInputPanel.jsx`: canopy treated as continuous everywhere canyon already is.
- `logic/pershing_api.py`: `CANOPY_MASK` global (bootstrap/persist/bake, same pattern as `SKETCH_WEIGHTS`), `BakeGrids.canopy` field (defaulted like `deck` — NOT undefaulted like `canyon`, since `legacy_diagram_bridge.py`'s Diagram Input path builds `BakeGrids`-shaped payloads with no canopy signal). 4 new `RebuildParams` fields: `canopy_base_height` (ft, default 20), `canopy_wave_amplitude` (default 3), `canopy_smoothing_iterations` (default 4), `canopy_puncture_threshold` (default 0.5).
- `frontend/src/components/ParamPanel.jsx`: "Canopy Engine" slider section.
- **New file `logic/canopy_engine.py`**: `CanopyEngine` class. Height equation = flat base + canopy-mask-scaled variable term (excavation dip + civic/sports program-zone crest, civic/sports categories = `sports_recreation`/`enrichment_civic`). Laplacian smoothing (`_smooth`, true neighbor-averaging, following `terracing_engine.py`'s `_relax_depths` flat-array idiom but averaging not clamping). Puncture logic: gated on boolean `is_shade`/`is_water` voxel flags AND the canopy mask's own continuous weight exceeding `canopy_puncture_threshold` (there's no continuous shade/water intensity to compare against instead — design decision, documented in the module docstring). `run()` returns `(height_matrix, puncture_mask, frame_specs)` — see item 6 below for `frame_specs`.
- Wired into `logic/pershing_api.py`'s `rebuild()`: instantiated after `zones` is computed (reuses it, doesn't recompute), response gets `canopy_height_matrix`/`canopy_puncture_mask` keys, and `frame_specs` gets merged into `all_specs` before serialization (see item 6).
- Also wired into `blender_cockpit.py`'s `rebuild_all()` (with `zones=[]` — that module has no `program_placement.py` integration at all, a pre-existing gap not backfilled here, so the civic/sports crest term is a no-op there).
- **Frontend viewport**: `frontend/src/components/Viewport.jsx`'s new `CanopyOverlay` component — builds a full nx×nz BufferGeometry grid surface (reusing `RealSlabPlate`'s technique, generalized), renders with `meshPhysicalMaterial` (first use of glass/transmission in this codebase: `roughness=0.05 transmission=0.9 thickness=0.5`). **This material may render nearly invisible without an environment map/strong lighting** — flagged but not yet fixed; see "known follow-ups" below.
- **Blender export**: `blender/pershing_headless_build.py` and `blender_cockpit.py` both got `build_canopy_mesh()` (continuous heightfield grid mesh, quad-per-cell, skips punctured cells) — verified via real headless Blender runs.

### 3. Ramp mesh mirror bug — root-caused and fixed
- User reported: "parking garage ramps on the hill side are not aligned with how they looked in the Rhino file."
- Root cause: `PershingMetabolizer_Prototype/extract_real_geometry.py`'s `mesh_site_local()` (the only source of real ramp face geometry, since the newer layered-OBJ ramp layer exports zero faces) never received the 2026-07-09 Z-axis-sign fix applied to every sibling element (`tunnel_mesh`, `secondary_entrance_mesh`, `column_positions`, etc.) — this left each ramp cluster's internal shape mirrored along the site's length axis, even though `build_real_geometry.py`'s later position-correction step correctly anchored the overall centroid.
- Fix applied directly to `PershingMetabolizer_Prototype/real_geometry.json` (the only available source — the original raw Rhino/OBJ extraction inputs for this specific stale ramp data are gone): mirrored each ramp level's vertices about that level's own current Z-bbox-center (verified via dry-run math first: this exactly undoes the bug without needing the original, now-unavailable extraction constants, since translation doesn't affect the bug and the position was already correctly anchored) and reversed face winding to restore correct normals.
- **Backed up first**: `PershingMetabolizer_Prototype/real_geometry.json.<timestamp>.bak` sits next to the fixed file. The file itself IS git-tracked, so `git diff`/`git checkout` is also available if this needs review/revert.
- Also regenerated `outputs/vector_export_test/site_named.obj` (the separate static OBJ `StaticContext.jsx` loads for the live web viewport's ramp/column/tunnel display) from the corrected `real_geometry.json`, via a one-off script calling `vector_export.py`'s existing `build_named_scene()`. Old file backed up alongside (`site_named.obj.<timestamp>.bak`). No committed script does this regeneration currently — worth turning into a real script if it needs to happen again.

### 6. Circulation paths → flat ribbons; canopy structural framework added (most recent work, unverified live due to the port issue)
- User: "grow network looks good, but can the pathways be a flat surface/slightly thickened polysurface rather than round tree branches."
