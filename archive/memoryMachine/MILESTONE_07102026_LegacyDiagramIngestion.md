Memory Machine — Legacy Diagram Ingestion Milestone
====================================================
*2026-07-10. Snapshot of a planning + implementation session adding an offline batch converter for the old diagram tool's exports — not a permanent spec.*

## Context

The old diagram tool (`static/main.js` + `app.py`'s `POST /api/export-diagram`) left ~222 color PNG/JPG exports at `archive/diagrams/generated/memory_machine_jpg-color_*.jpg`, each encoding real site-design intent: green fill = greenscape, blue fill = water features, gray/hatched fill = hardscape (including dotted-line paths), dashed white line = site boundary. That tool rendered the site **true-north-up**, so the site rectangle itself appears rotated in the image (DTLA's street grid runs the site at roughly 36-52° off true north). The current live pipeline (`terracing_engine.py` + `logic/pershing_api.py` + `PaintOverlay.jsx`) works in an **orthogonal** frame aligned to the site's own street grid instead (`vector_export.py`'s `STREET_LABELS`: Olive=x0, Hill=xmax, 6th=y0, 5th=ymax) — no rotation applied anywhere. Goal: rectify the diagonal exports into that orthogonal frame and feed the design intent into the live pipeline, rather than losing it.

User decisions made before implementation: dotted-line "paths" fold into the existing `hardscape` category (the live pipeline only has `canyon`/`hardscape`/`water_shade`/`greenscape`/`amenity_resting` — no dedicated path typology); this ships as an **offline batch converter**, not a live-upload UI feature.

## What shipped this session

1. **`ingest_legacy_diagram.py`** — the main pipeline. `detect_boundary_affine()` thresholds the dashed white boundary and runs `cv2.minAreaRect` on the raw point cloud (works across dash gaps, no contour closing needed) to recover each image's own rotation/crop, per-image rather than shared (see bug note below on why). `segment_legacy_colors()` thresholds original (unwarped) pixels against `harvest/pershing_square_generator.py`'s `COLOR_MAP` RGB legend, restricted to the boundary polygon's interior via `sketch_weight_mapper._points_in_polygon`. `BoundaryAffine` transforms segmented points into site-local feet; `rasterize_to_paint_state()` bins them into the exact voxel grid `TerracingEngine` uses. Output matches `outputs/cockpit/web_paint_state.json`'s shape exactly, so `logic/pershing_api.py`'s existing bootstrap-load branch picks it up with zero pipeline code changes. CLI: single image, `--batch` (writes `outputs/legacy_diagram_ingest/<epoch_ms>.json` + a `manifest.csv` for spot-checking), `--debug` (plan-view PNG preview), `--install-as-live`.
2. **`calibrate_legacy_orientation.py`** — one-time calibration tool. `cv2.minAreaRect`'s angle is mod-90° and can't resolve which side of the rectangle is which street; this renders all 4 `(flip_x, flip_y)` hypotheses with `vector_export.py`'s `STREET_LABELS` burned onto the original image via `BoundaryAffine.inverse_transform`, for visual sign-off against known geography.
3. **Empirically verified color legend** (sampling real quantized pixel values across 3 sample images): green ≈(72-80,168-176,72-80), water/blue ≈(0-8,160-169,232-244), hardscape gray ≈(144-160,144-168,144-160) — this also covers the hatched/stippled path texture, confirming plain black is background/unpainted, not a separate hardscape fill (an initial visual-inspection worry that turned out to be wrong).
4. **Orientation calibration confirmed**: `FLIP_X=False, FLIP_Y=False`, cross-checked against DTLA street geography (5th=north/top, 6th=south/bottom, Olive=west/left, Hill=east/right) and internally validated (`TT`, the exact opposite flip, gets both axes wrong; `FT`/`TF`, single-axis flips, each get exactly one axis wrong — fully self-consistent).
5. **Full batch converted**: all 222 `memory_machine_jpg-color_*.jpg` → `outputs/legacy_diagram_ingest/*.json`, 0 errors. Painted-area-fraction outlier (0.60 vs. a ~0.05 mean) manually checked against its source image and confirmed to be a genuinely denser design, not a segmentation failure.

## Two real bugs found and fixed mid-session (both now documented in code comments)

1. **Axis-swap bug in the rectification transform.** `cv2.minAreaRect`'s `rot_x` always spans its own `w` and `rot_y` always spans `h`, regardless of which is longer — the first implementation assumed rotating the *angle* by 90° when `w < h` would fix axis assignment, which is wrong; the fix swaps which *component* (`rot_x` vs `rot_y`) maps to width vs. length instead. This flipped the orientation-calibration conclusion: the first (buggy) determination pointed to `flip_x=False, flip_y=True`; after the fix, re-verification against DTLA geography and the internal self-consistency check above showed `flip_x=False, flip_y=False` is actually correct.
2. **Shared-affine bug in batch conversion.** The corpus has images at different pixel resolutions (confirmed: some 2448×1584, others 1221×1284) even though rotation angle and aspect ratio are consistent across the whole batch. The first `convert_batch()` implementation detected one `BoundaryAffine` from a handful of sample images and reused its absolute pixel-space `center_px`/`box_w_px`/`box_h_px` for every image — silently misaligning most of them (caught via a live-app spot check: the shared-affine version produced 63 greenscape cells for the reference image where per-image detection produces the correct 1541). Fixed: `calibrate_batch_affine()` now runs purely as a consistency check (validates angle/aspect agreement across a sample); every image gets its own freshly-detected affine for the actual transform.

## Data loss incident (own testing, not the feature itself)

`install_as_live()`'s first version backed up any existing `outputs/cockpit/web_paint_state.json` to a fixed `.bak` filename. Calling it twice in a row (once with the since-fixed-buggy conversion, once with the corrected one) silently overwrote the first backup — which held the user's real hand-painted original state — with the buggy intermediate conversion. Not tracked in git, no other copy existed; the original is unrecoverable. User confirmed: leave the corrected legacy-diagram conversion installed as the current live state rather than trying to reconstruct the lost original. Fixed `install_as_live()` to use a timestamped backup filename (`web_paint_state.json.<epoch>.bak`) so a repeat call can never clobber an earlier backup again.

## Verified

- `detect_boundary_affine` tested against 10 sample images: rotation angle agrees within ~0.03°, aspect ratio within ~0.003 — confirms the whole corpus shares one renderer/scene setup (used only as a consistency check, not to justify affine reuse, per bug #2 above).
- End-to-end `convert_one()` on the calibration reference image, rendered via `render_debug_preview()`: rectified plan clearly recognizable against the original diagonal JPG — green surround, gray hardscape plaza shape, and diagonal blue water band all match.
- Full 222-image batch: 0 errors; manifest outlier manually cross-checked against its source image.
- Live-app round trip: installed a converted diagram via `--install-as-live`, restarted a `uvicorn app:app` instance on an alternate port (the original dev server on :8000 turned out to be an unkillable orphaned process — Windows' process list has no matching PID for it, but it still answers requests; flagged for the user to deal with directly), hit `POST /api/pershing/rebuild`, confirmed all 1541 greenscape cells appear correctly in the response.

## Known gaps / next up

1. **Port 8000 anomaly unresolved.** Something is still serving stale (pre-session) data on `127.0.0.1:8000` that neither `taskkill` nor PowerShell `Stop-Process`/`Get-Process` can find by PID. Needs the user's own investigation (Task Manager, or a reboot) before the app is used there again.
2. `outputs/legacy_diagram_ingest/*.json` (222 files) and the live `outputs/cockpit/web_paint_state.json`/`.bak` are intentionally **not** committed this session — regenerable derived output and ephemeral single-session state respectively, matching this repo's existing convention of not tracking `archive/diagrams/generated/` and similar derived artifacts. Re-run `python ingest_legacy_diagram.py --batch` to regenerate.
3. Only one of the 222 converted diagrams has been installed/spot-checked live end-to-end (the calibration reference image). Worth spot-checking a few more — especially the painted-area-fraction outliers from `manifest.csv` — before treating the whole batch as trustworthy design input.
4. The unidentified secondary dashed line seen inside the boundary in some sample images (parallel-offset, doesn't match any documented color) was never resolved — likely a setback/inset annotation to ignore, not confirmed.
