## What This App Is

**Memory Machine** is a single-page architectural cross-pollination tool for redesigning Pershing Square, DTLA. It lets you:
1. Pull diagram layers from 4 reference parks (Pershing Square, Schouwburgplein, Parc de la Villette, Zaryadye Park)
2. Stack them in a 2D remix canvas clipped to the Pershing Square boundary
3. Preview in a lofi isometric 3D inset or full 3D tab
4. Export as SVG or JPEG (color + linework modes)
5. Deploy to AI-informed 3D via a Draft/Dream mode toggle
6. Bake back to Rhino

**Stack:** FastAPI (`app.py`) + vanilla JS single-page app (`templates/index.html`) + CSS (`static/style.css`). No build step.

## Changes Made This Session

### 1. Deploy to 3D — Fixed (`templates/index.html`)
The old `deployTo3D()` checked `MemoryState.precedentSVG` (removed architecture). Fully rewritten to:
- Guard on `MemoryState.stack.length === 0`
- Iterate each visible stack item using the same transform math as the 2D render (`fitScale = min(bbox.w/precVB.w, bbox.h/precVB.h)`, `ts = fitScale * item.scale`)
- Render as `THREE.Line` objects (not `ExtrudeGeometry`) — Rhino SVGs export open line segments, not closed shapes, so extrusion always failed silently
- Center everything at world origin `(0,0,0)` — camera `lookAt(0,0,0)` always correct

## ComfyUI Integration — What Needs Wiring

The pipeline is fully structured. In `app.py`, replace the stub:

```python
def generate_comfyui_mesh(prompt: str, footprint: dict) -> dict:
    # Current stub — replace with:
    workflow = build_comfyui_workflow(prompt, footprint)
    res = requests.post("http://localhost:8188/prompt", json={"prompt": workflow})
    glb_path = poll_comfyui_output(res.json()["prompt_id"])
    # Copy glb to static/generated/
    return {"glb_url": f"/static/generated/{os.path.basename(glb_path)}", "footprint": footprint}
```

Frontend expects each mesh item:
```json
{
  "glb_url": "/static/generated/something.glb",
  "footprint": { "cx": 0.0, "cz": 0.0, "width": 12.3, "depth": 8.7, "rotRad": 0.0 },
  "site": "Schouwburgplein",
  "layerId": "SHADE",
  "label": "Shade"
}
```

Three.js auto-scales/positions the GLB to fit `footprint.width × footprint.depth` centered at `(cx, 0, cz)`.

## Known Issues for Gemini to Resolve

### Priority 1 — Coordinate space mismatch
The OBJ model vertices are ~±1300 units (Rhino model space).
Stack layer lines use `SVG_SCALE = 0.04` so they sit at ~±25 units.
These two spaces don't overlap — stack layers won't appear over the OBJ.

**Option A:** Scale OBJ down after load:
```javascript
const S = box.getSize(new THREE.Vector3());
const targetSize = 50; // match SVG_SCALE world
obj.scale.setScalar(targetSize / Math.max(S.x, S.z));
```
**Option B:** Increase `SVG_SCALE` to match OBJ units (~`SVG_SCALE = 1.0` and recalibrate camera).

### Priority 2 — OBJ vertical orientation
Rhino may have exported Z-up. If the model appears on its side:
```javascript
obj.rotation.x = -Math.PI / 2;
```

### Priority 3 — Lofi inset base context
Currently draws SVG layer lines. Once OBJ scale is resolved, consider loading a decimated version of the OBJ in the inset too (or keep SVG lines at matched scale).

### Priority 4 — `/api/generate` vs `/api/generate-3d` unification
The original Generate Intervention button still produces box/cylinder geometry via the old `build_geometries()` path. Consider whether to unify this with the new footprint pipeline or keep as a separate narrative-only flow.
