## What the App Does Right Now

Memory Machine is a single-page architectural remix tool for Pershing Square, DTLA. The workflow is:

1. **2D Remix tab** — Load diagram layers from 4 reference parks, stack them onto the Pershing Square boundary, clip to the actual park outline, export as SVG/JPEG
2. **3D Preview tab** — Opens to show the Rhino OBJ model of Pershing Square immediately (before any generation). "Deploy to 3D" draws the remix stack on top as 3D lines. "Dream to 3D" (Dream mode) sends footprints to the AI backend for mesh generation via ComfyUI (stub ready, not yet connected)
3. **Generate Intervention** — AI narrative + precedent search via Gemini + ChromaDB
4. **Bake to Rhino** — Sends geometry back to the live Rhino session

**Stack:** FastAPI (`app.py`) + vanilla JS SPA (`templates/index.html`) + CSS (`static/style.css`). No build step. Run with `uvicorn app:app --reload`.

## Changes Since Last Handoff (04-03 → 04-04)

### Lofi 3D Inset — Removed
The lofi isometric side-panel in the 2D tab was removed entirely:
- Deleted the HTML panel (`#remix-inset-wrap`, canvas, label)
- Deleted the "Lofi 3D" toggle button from the left panel
- Removed `toggleLofiPreview()`, all inset renderer/scene/camera variables, and the full `updateRemixInset()` body (replaced with a no-op stub for call-site safety)
- Removed `insetScene` background update from `toggleTheme()`
- Focus is now entirely on the full 3D Preview tab

### 3D Preview Tab — Auto-loads OBJ on First Click
Clicking "3D Preview" now immediately:
1. Calls `initSceneShell()` (sets up Three.js scene, camera, renderer, lights, orbit controls)
2. Calls `buildPershingContext()` which loads `models/rhino/PershingSQCurrent.obj` + `.mtl` via `MTLLoader` → `OBJLoader`
3. Auto-centers model using `Box3.getCenter()`, adjusts camera radius to `max(width, depth) × 1.2`
4. Shows progress % in status bar during the 432k-line OBJ load
5. Falls back to a plain grey `MeshStandardMaterial` if MTL fails

The 3D tab is now a "before/after" — OBJ is the "before", Deploy to 3D adds remix layers on top as the "after".

### 2D Clip Path — Polygon Instead of Rectangle
The `clipPath` used to clip stack layers to the Pershing Square boundary was previously a bounding-box **rectangle**. It is now a **polygon** traced from the actual BOUNDARY path coordinates:
- New function `buildBoundaryClipPath(svgEl, ns, clipId)` collects the first coordinate from each BOUNDARY path segment (Rhino exports them sequentially around the perimeter), builds a `<polygon>` element
- Used in both `renderRemixSVG()` (live view) and `buildExportSVG()` (exports)
- Fallback to bbox rect if fewer than 3 points are found

### Site Context Color — Mode-Independent Grey
Buildings, streets, and parking in the 2D base map used to be near-black (`#1e1e1e` fill, `#3a3a3a` stroke) — invisible in dark mode and illegible in light mode.
- Now fixed at `#aaaaaa` fill / `#888888` stroke at 75% opacity
- Reads clearly in both dark and light mode
- Applied in both live render and export

### Clear Stack Button
- "Reset transform" button renamed to **"Clear Stack"**
- Now calls `resetAll()` which: empties `MemoryState.stack`, resets transform, clears editing state, re-renders the 2D canvas back to just the Pershing Square base, autosaves
- Pershing Square SVG stays cached — base map reappears immediately

### PARKING::entrances — Robust Strip
The sublayer removal changed from `querySelector('[id="PARKING::entrances"]')` (exact match, direct child only) to:
```javascript
c.querySelectorAll('[id*="entrances"], [id*="Entrances"]').forEach(el => el.remove());
```
Catches the element at any nesting depth and any casing.

### Light Mode — White Canvases
In light mode, `#remix-canvas-wrap`, `#tab-canvas`, `#remix-inset-wrap`, and `#canvas-placeholder` are all forced to `#ffffff` via CSS. Three.js scenes also get white backgrounds when light mode is active at scene init time.

## Key JS Functions (index.html)

| Function | What it does |
|---|---|
| `MemoryState` | `{ stack[], svgCache{}, dreamMode, editingId, transform, currentCompositionName }` |
| `renderRemixSVG()` | Builds the 2D SVG: bg → site context → stack items (all clipped to boundary polygon) |
| `buildExportSVG(mode)` | Same as renderRemixSVG but for export; mode = `'color'` or `'linework'` |
| `buildBoundaryClipPath()` | Builds `<polygon>` clipPath from actual BOUNDARY path coords |
| `initSceneShell()` | Sets up Three.js scene, camera (perspective, far=20000), renderer, lights, ground, orbit controls |
| `buildPershingContext()` | Loads OBJ/MTL from `/models/rhino/`, auto-centers, sets camera distance |
| `deployTo3D()` | Draft: draws stack as `THREE.Line` objects. Dream: POSTs footprints to `/api/generate-3d` |
| `_drawStackLines()` | Iterates `MemoryState.stack`, renders each layer as 3D lines using SVG coordinate math |
| `extractFootprints()` | Computes `{ cx, cz, width, depth, rotRad }` per stack item for backend |
| `pathTo3DLines()` | Shared SVG path → `THREE.Line` converter |
| `toggleTheme()` | Toggles `body.light-mode`, updates Three.js bg, re-renders 2D SVG |
| `resetAll()` | Clears stack + transform, re-renders base map |
| `loadSVGFile(event)` | File picker → registers SVG in `svgCache`, adds to site dropdown |
| `setDreamMode(on)` | Switches Deploy button between Draft and Dream ✦ modes |

## Known Issues / What Needs Work

### Priority 1 — OBJ ↔ SVG Coordinate Space Mismatch
The OBJ model vertices are ~±1300 units (Rhino model space).
Stack layer lines from `_drawStackLines()` use `SVG_SCALE = 0.04` → ~±25 units.
These don't overlap — if you Deploy to 3D, the stack lines appear near origin but the OBJ is at a completely different scale.

**Two options:**
- **A (recommended):** After OBJ loads, scale it down to match SVG world space:
  ```javascript
  const targetSpan = bbox.w * SVG_SCALE; // ~25 units
  const objSpan = Math.max(size.x, size.z);
  obj.scale.setScalar(targetSpan / objSpan);
  ```
- **B:** Increase `SVG_SCALE` from `0.04` to match OBJ units and recalibrate camera

### Priority 2 — OBJ May Appear Underground or On Its Side
Rhino exports can be Z-up. If the model appears sideways:
```javascript
obj.rotation.x = -Math.PI / 2;
```

### Priority 3 — ComfyUI Bridge (Stub Only)
`generate_comfyui_mesh()` in `app.py` currently returns `{ glb_url: null }`.
When ComfyUI is running at `localhost:8188`, replace with:
```python
workflow = build_comfyui_workflow(prompt, footprint)
res = requests.post("http://localhost:8188/prompt", json={"prompt": workflow})
glb_path = poll_comfyui_output(res.json()["prompt_id"])
return {"glb_url": f"/static/generated/{os.path.basename(glb_path)}", "footprint": footprint}
```
Frontend expects `glb_url`, `footprint`, `site`, `layerId`, `label` per mesh item.

### Priority 4 — 3D Tab Init Race Condition
`buildPershingContext()` fires 100ms after tab click to allow browser layout. If the machine is slow the canvas may still be 0×0. Consider using a `ResizeObserver` on `#three-canvas` instead of a fixed timeout.
